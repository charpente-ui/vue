# Audit: library source (bugs, a11y, optimizations, comparison with other headless libs)

Date: 2026-11-20
Baseline commit: 9def8bc
Scope: src/ (all components and internal composables), compared with Headless UI, Reka UI, Ark UI, Radix Form, VeeValidate, FormKit
Status: open

## Findings

| ID | Severity | File | Problem | Status | Notes (commit / reason) |
|----|----------|------|---------|--------|-------------------------|
| A1 | medium | src/components/BaseSupportingText.vue:41-47 | `role="alert"` (assertive) on a validation text: once a field is invalid, `syncValidity` updates the message on every keystroke, and native messages can embed live counts (Chrome `tooShort`: "you are currently using 3 characters"), so screen readers are interrupted at each key. The role is also present while the plain hint is shown. Consider `aria-live="polite"`, or announcing only on submit/blur. | fixed | Validation text is now a permanent `aria-live="polite"` region, no implicit `role`. |
| A2 | medium | src/components/internal/field.ts:65-68, src/components/BaseSupportingText.vue:49-59 | SSR: a supporting text registers in its own setup, after a control rendered before it (the usual label/input/hint order) has already been rendered, so the server HTML has no `aria-describedby`; it only appears after hydration, through an extra re-render (also on CSR). | open | |
| A3 | low | src/components/internal/modifiers.ts:54-71 | With `.trim`/`.number`, a value set by the app (e.g. `'  a '`) is pushed into `raw`, the sync watcher normalizes it and emits `update:modelValue('a')`. Vue's native `v-model.trim` never writes the model back on a programmatic change. | wontfix | Confirmed by a throwaway test (trim: `'  a '` -> `'a'`, number: `'42'` -> `42`). Normalizing an app-set value is accepted. |
| A4 | low | src/components/BaseSelect.vue:18, 49, 58, 78 | `<CSelect multiple>` with an unbound or `undefined` model makes Vue warn "expects an Array or Set". Keys collide for `1` vs `'1'` (`option:1`) and for two groups with the same label (duplicate-key warnings, wrong patching). | fixed | Multiple select binds `[]` for a non-array model; option keys include the value type and repeated keys get an occurrence suffix. |
| A5 | low | src/components/internal/field.ts:65 | `registerSupportingText` does not dedupe: two supporting texts with the same explicit `id` produce a repeated id in `aria-describedby`. | fixed | `describedBy` dedupes ids with a Set; the list is untouched so one remaining text stays referenced. |
| A6 | low | src/components/BaseLabel.vue:26, BaseCheckbox.vue:25, BaseRadio.vue:24 | Unguarded `process.env.NODE_ENV`: without a bundler (import map, raw CDN ESM) setup throws `ReferenceError: process is not defined`. Either guard it (`typeof process !== 'undefined'`) or document that the build targets bundlers only. | open | |
| A7 | low | src/components/internal/field.ts:202 | `useFieldGroup` always creates its own `useFieldState` (form `reset` listener, mount hooks, refs) even inside a CField, where it is unused. | fixed | `useFieldGroup` only calls `useFieldState` when there is no outer CField; handlers are no-ops otherwise. |
| A8 | low | src/components/internal/field.ts:89-94 | A CField holding several controls (date range) follows only the control that fired the last event: fixing one clears the field's invalid state while another control is still invalid. | fixed | Field keeps a Set of controls flagged invalid; stays invalid until all are valid or disconnected. |
| A9 | low | src/components/internal/element.ts:11 | `instanceof HTMLElement` returns `null` for an SVG root (`as="svg"` or a component rendering one); `Element` would cover it. | open | |
| A10 | low | src/components/BaseRadio.vue:14, BaseCheckbox.vue:14, src/components/internal/keys.ts | Group models are typed `string \| number` while item `value` is `unknown` (documented). Generic components (`<script setup generic="T">`) would let TypeScript infer and enforce the value type end to end. | open | |
| I1 | improvement | src/components/BaseSupportingText.vue, BaseField.vue | Messages are the browser's native ones, in the browser's locale, not the app's. Radix Form (`Form.Message match="valueMissing"`) and VeeValidate/FormKit let the app map each validity key to its own message. Add a per-`ValidityState` key mapping (and expose the validity snapshot). | open | |
| I2 | improvement | src/components/BaseField.vue | No way to flag a field invalid from outside (server error): Ark UI `Field.Root invalid`, Radix `serverInvalid`. Today only a `rule` plus a manual `reportValidity()`, because the invalid flag is only set by the `invalid` event. | open | |
| I3 | improvement | src/components/BaseField.vue | `disabled` / `required` / `readonly` on CField do not reach the control (Headless UI `Field disabled`, Ark UI Field propagate them). Groups get it natively from `<fieldset disabled>`, CField (a `<div>`) does not. | open | |
| I4 | improvement | src/components/BaseButton.vue | `disabled` with a non-button `as` (`a`, `div`) has no effect: no `aria-disabled`, no click guard, still focusable. Reka UI / Headless UI handle it. | open | |
| I5 | improvement | src/components/internal/field.ts | Errors only show after a submit attempt. VeeValidate modes / FormKit `validation-visibility` / native `:user-invalid` also allow "after blur" or "live"; a `validate-on`-style option on CField/CForm would cover them. | open | |
| I6 | improvement | src/components/BaseForm.vue:61-66 | `invalid-submit` only passes the event. Passing the list of invalid controls (element, name, message) would allow an error summary without re-walking `form.elements` (VeeValidate/FormKit expose an errors map). | open | |
| I7 | improvement | src/index.ts | Missing components common to headless form libs: CSwitch (`role="switch"`, Headless UI/Reka/Ark), number field, pin input; combobox/listbox are larger scope. To decide whether they fit the library's scope. | open | |
